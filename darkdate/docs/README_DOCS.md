## 📋 Как работать с документацией

### Для разработчиков

1. **Перед началом работы:**
   - Прочитайте [`GDD.md`](GDD.md) для понимания концепции
   - Изучите [`ARCHITECTURE.md`](ARCHITECTURE.md) для структуры кода
   - Проверьте [`CHANGELOG.md`](CHANGELOG.md) для последних изменений

2. **В процессе разработки:**
   - Сверяйтесь с GDD при реализации новых функций
   - Следуйте архитектурным принципам
   - Записывайте изменения в CHANGELOG

3. **Перед коммитом:**
   - Убедитесь, что код соответствует архитектуре
   - Обновите CHANGELOG если нужно
   - Проверьте, не требует ли изменений документация

### Для геймдизайнеров

- Основной документ: [`GDD.md`](GDD.md)
- Предлагайте изменения через Issues или PR
- Обновляйте разделы GDD при изменении дизайна

### Для всех

- Этот файл ([`README_DOCS.md`](README_DOCS.md)) — точка входа
- [`CHANGELOG.md`](CHANGELOG.md) — что нового
- Главный [`README.md`](../../README.md) — общая информация о проекте

## 🔧 Обновление документации

### Правила

1. **Все изменения в коде** → запись в [`CHANGELOG.md`](CHANGELOG.md)
2. **Изменение механик** → обновление [`GDD.md`](GDD.md)
3. **Изменение структуры** → обновление [`ARCHITECTURE.md`](ARCHITECTURE.md)
4. **Новые технологии** → обновление [`TECH_STACK.md`](TECH_STACK.md)

### Формат коммитов

```
docs: обновить описание модуля swipe в ARCHITECTURE.md
feat: добавить систему чатов (обновить GDD.md и CHANGELOG.md)
fix: исправить баг с таймером (обновить CHANGELOG.md)
```
